# DAY 6 - Mixed Pattern Practice

## Goal

Train your brain to:

> See a problem → instantly map it to a pattern → execute cleanly

This is where interview readiness starts.

---

# Core Skill

You are practicing:

> **Pattern switching under pressure**

Not solving - **recognizing fast**

---

# Problems Set

* Move Zeroes
* Container With Most Water
* Longest Substring Without Repeating
* Subarray Product < K
* Valid Palindrome
* Longest Repeating Character Replacement

---

# Step 1 - Pattern Identification Drill (MOST IMPORTANT)

Before solving each problem, force yourself to answer:

| Problem               | Pattern                             |
| --------------------- | ----------------------------------- |
| Move Zeroes           | Two pointers (same direction)       |
| Container             | Two pointers (opposite)             |
| Longest Substring     | Sliding window                      |
| Product < K           | Sliding window (variable condition) |
| Palindrome            | Two pointers (symmetry)             |
| Repeating Replacement | Sliding window (frequency-based)    |

If this is NOT instant → stop and revise.

---

# Step 2 - Decision Framework (30-second rule)

For each problem, ask:

## 1. Is it subarray/substring?

→ YES → Sliding Window

## 2. Is it pair / max-min / symmetric?

→ YES → Two Pointers

## 3. Is it rearrangement / filtering?

→ YES → Two pointers (same direction)

---

# Step 3 - Execution Focus

## For Two Pointers

Ask:

* Why is left moving?
* Why is right moving?

---

## For Sliding Window

Ask:

* What is the condition?
* When do I shrink?
* What state am I tracking?

---

# Step 4 - Time Targets

* Easy → 5–7 minutes
* Medium → 10–15 minutes

If you exceed:
→ pattern is not internalized yet

---

# Step 5 - Mistake Tracking (VERY IMPORTANT)

After each problem, write:

* Did I pick wrong pattern?
* Did I hesitate?
* Did I mess pointer movement?

This is how you improve fast.

---

# Common Failure Points

## 1. Confusing patterns

Example:

* Using sliding window where two pointers is enough

---

## 2. Wrong shrinking logic

* Shrinking too early / too late

---

## 3. Forgetting state updates

* Not updating frequency / product properly

---
